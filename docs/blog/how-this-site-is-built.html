How this site is built: bilingual, static, one script

2026-09-06 · metatooling

This site is a single Python script. It reads a BibTeX file, two YAML files and a folder of markdown, and writes plain HTML into a docs/ directory that GitHub Pages serves. No Jekyll, no Hugo, no JavaScript build. The reasons are worth writing down, because they are the same reasons I make most tooling decisions.

One source of facts

The publication list is the only thing on this site that other people will check. It comes from a publications.bib that can be run through a DBLP / arXiv fact-checker, and every page that mentions a paper renders it from that file. The prose is allowed to be opinionated; the facts are not allowed to drift.

Two languages, two URL trees

Rather than toggling text with JavaScript, every page exists twice:

English中文
/agent.html/zh/agent.html
/blog/<slug>.html/zh/blog/<slug>.html
/feed.xml/zh/feed.xml

The language button in the top-right corner is just a link to the sibling page, and each page carries hreflang links to the other. A shared link therefore always opens in the language the sender was reading, and search engines see two real pages instead of one page that changes shape. The only script involved remembers the last choice in localStorage and applies it when you land on the root URL.

The Chinese content is a sparse overlay on the English structure — a YAML file with the same shape that only carries translated strings. Everything factual (publication keys, links, numbers) is inherited, so a translation cannot accidentally introduce a new claim:

def merge(base, over):
    if isinstance(base, dict) and isinstance(over, dict):
        return {k: merge(base[k], over[k]) if k in over else v for k, v in base.items()} | \
               {k: v for k, v in over.items() if k not in base}
    if isinstance(base, list) and isinstance(over, list):
        return [merge(b, o) for b, o in zip(base, over)] + base[len(over):]
    return over

Comments and counting without a backend

GitHub Pages hosts files, nothing else. Comments are giscus: each post maps to a GitHub Discussion in the site's own repository, so the data lives with the source and readers sign in with an account they already have. Both language versions of a post point at the same discussion.

Visits are counted by GoatCounter, which stores no personal data and needs no cookie banner. Whether the number is shown on the page is a one-line switch; by default it is not.

The test for every piece of this stack was the same: if the service disappears, does the site still build? For all three answers the answer is yes — the worst case is a missing comment box.
