智能体与后训练

我关心智能体在长时间运行中为什么会失败。一部分工作从理论入手，研究任务结构造成的限制；另一部分工作是搭建评估系统，观察实际的失败过程，再通过后训练改善表现。

我通常先分析失效原因，再设计对应的实验和工程方案。理论需要能被检验，评测也需要说清楚测到的是什么。这两方面的工作会相互修正。

理论

研究任务本身对系统能力的限制。

多智能体成功率的信息论极限

这项工作从任务结构推导多智能体成功率的上界：任务的分解方式会限制协作系统能够获得的信息，进而限制成功率。我们在 SWE-bench 上检验了理论预测，并据此研究可以改善可靠性的机制。

生存压力下的终身学习

我尝试从受约束学习的角度形式化终身学习，把生存压力纳入遗忘与可塑性的权衡。相关 arXiv 论文和 PAVO 战略文档正在准备，也在搭建配套基准（见下文压力下的长程自主）。

通过流形保持优化对抗可塑性丧失

研究 MLP/CNN 的权重分布与可塑性之间的关系。实验中，保持流形结构的优化方案能更好地缓解可塑性丧失。相关工作正在准备。

实践

环境 → 轨迹 → 评估器 → 奖励 → 后训练，再回到环境。

评估：把行为变成信号

我在评估上主要做了三类工具：检查单智能体的工具使用行为，让不同智能体的运行结果可以复现和比较，以及在手写测试成本过高时自动生成领域评估集。这些评估结果也用于后训练。

  • eval-box — 确定性检查与 LLM 评审
    结合四项确定性检查（工具名、AST diff、参数一致性、输出格式）与 LLM 评审，使用统一的轨迹格式。评估器可独立运行，也可以评估其他输出同一格式的智能体。
  • 受控轨迹协议
    固定沙箱配置，明确数据污染规则，将不同 CLI 智能体的运行记录整理成统一的 JSONL 轨迹，便于复现和比较。
  • AutoGT — 评估集自动生成
    利用领域先验引导智能体从真实企业软件系统中提取知识，生成 QA 评估集。生成测试给出的系统排名与专家手写测试高度一致，也覆盖了绝大多数专家定义的类别。已用于产品，方法论文正在审稿。
    论文 · 审稿中
  • 27 项认知算子评估
    根据人类工作记忆与元认知理论设计 27 项算子评估，用于系统比较三大闭源模型家族。

面向可验证行为的后训练

企业部署智能体时，需要它持续、稳定地完成工作。我在 PAVO 提出了程序化过程奖励：用神经符号方法从运行轨迹中提取可计算的奖励信号，再用于 DPO/GRPO 后训练。

  • 程序化过程奖励 → DPO/GRPO
    用这套方法微调 Qwen2.5-0.5B 后，内部工具行为评估得分比基座模型提高约 10%。评估主要考察模型能否识别工具调用期间由随机采样或上下文注入引入的非法操作。
  • 从种子批量生成评估环境
    为支持这项评估，我构建了一个环境生成智能体。它根据环境图生成工具列表和依赖库各异的 Docker 镜像，用少量种子环境和一个 LLM 批量构造测试环境。

压力下的长程自主

有些问题要运行足够久才会出现。下面两个环境都跟踪系统随时间的退化，记录代码质量、决策和运营结果如何变化，以及系统最终能维持多久。

  • Mini-Uber — 多智能体运营的压力测试
    在规则不可由智能体修改的曼哈顿规模网约车仿真中，模拟需求、用户分布、拥堵和暴雨。coder 与 manager 两层智能体负责维护派单代码库，并应对逐渐增大的外部压力。引入竞争与监管信号后，系统存活时长大约减半。代码质量在运行早期就开始下降；随后 manager 的预测越来越缺乏依据，并出现幻觉，代码库最终崩溃。
  • 长期代码库维护的终身学习基准
    在截至 2026 年初的系统综述中，我们没有找到评估智能体独立开发、运营长期代码库的长程编码基准。为此构建了四个相互独立、几乎不含人工代码的软件项目，从开源仓库提取候选功能，经专家审核后形成指令池，再要求智能体根据提取的 issue 持续维护。多数架构在预期时长之前便已失败，仓库质量分数持续下降。

生产系统中的应用

我加入 PAVO 后，第一个月完成了上下文压缩组件的开发，并将其提交到生产代码库。

  • 动态上下文压缩 — 压缩率翻倍以上
    阅读生产代码后，我发现原有方案主要按规则选取部分轮次内容，没有对当前轮次做语义压缩。我结合 LLMLingua-2 与 Qwen2.5-0.5B，实现字节级过滤与压缩。在复杂工具调用场景中，反事实消融显示智能体性能基本不变，压缩率提高到原来的两倍以上。从定位问题到演示用了约一周，一个月内通过 PR 引入生产代码。后续工作按我参与制定的计划移交工程团队。
