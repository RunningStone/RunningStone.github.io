智能体与后训练

我同时做同一个问题的两端。理论告诉我长程智能必然在哪里失效——那些无论系统工程做得多好都成立 的极限。实践是度量它是否真的失效的基础设施，以及把边界往外推的后训练。

顺序对我很重要：我倾向于先刻画一种失效模式，再围绕它做工程。但任何一半单独存在都价值有限——没人 能度量的上界只是个奇观，而没有理论说明自己在界定什么的基准只是个排行榜。

理论

无论工程做得多好都成立的极限。

多智能体成功率的信息论极限

一个从任务结构而非模型能力出发推导的智能体失效上界理论：给定任务如何分解，任何多智能体 安排所能达到的成功率都有一个天花板。在 SWE-bench 上得到验证，并延伸到由此导出的可靠性机制 ——上界不是论证的终点，而是告诉工程该往哪里发力的东西。

生存压力下的终身学习

一个完整的终身学习形式化，与通行框架的分野在于受约束学习的视角：遗忘–可塑性权衡并不在抽象 中运作，而是在生存压力下运作。将作为 arXiv 论文与一份 PAVO 战略文档一同提交，并附带一个基准 （见下文*压力下的长程自主*）。

通过流形保持优化对抗可塑性丧失

研究 MLP/CNN 网络的可塑性与其权重分布之间的关系。一种流形保持的优化方案表现出更强的抗可塑性 丧失行为。（准备中。）

实践

环境 → 轨迹 → 评估器 → 奖励 → 后训练，再回到环境。

评估：把行为变成信号

后训练闭环的上限由喂给它的评估器决定。三件互补的东西：面向*单智能体工具行为*的确定性检查加 判官模型的评测框架、让跨智能体比较有意义的可复现层，以及在手写测试代价过高时自动生成*领域 评估集*的生成器。

  • eval-box — 确定性检查 + LLM 判官
    四项确定性检查（工具名、AST diff、参数一致性、输出格式）与 LLM 判官在同一套轨迹 schema 上组合。独立运行，任何输出该 schema 的智能体都能被评分。
  • 受控轨迹协议
    在固定沙箱和显式污染规则下，为各 CLI 智能体产出可比较的规范化 JSONL 轨迹——没有这一可复现层，跨智能体的数字毫无意义。
  • AutoGT — 评估集自动生成
    一条由领域先验引导的智能体流水线，从真实企业软件系统中抽取知识并转化为 QA 评估集。生成的测试对系统的排序与专家手写测试高度一致，同时覆盖了绝大多数专家定义的类别。已交付进产品；方法论文审稿中。

面向可验证行为的后训练

企业级智能体的部署取决于*有保证、稳定的服务*，而不是平均意义上的能力。我在 PAVO 自发提出了 程序化过程奖励这一方向：一个神经符号框架，把观察到的轨迹结构转化为程序化奖励信号，进而 驱动 DPO/GRPO 流水线。

  • 程序化过程奖励 → DPO/GRPO
    以此方式微调 Qwen2.5-0.5B，在内部工具行为评估上相比其自身基座提升约 10%——主要体现在检测工具调用期间通过随机采样或上下文注入引入的非法操作。
  • 从种子批量生成评估环境
    为使上述评估成为可能，构建了一个智能体：利用环境图构造工具列表，并生成依赖库各异的差异化 Docker 镜像——从少量种子和一个 LLM 得到大量测试环境。

压力下的长程自主

短程基准掩盖了真正重要的失效模式。下面两个环境的设计目标都是让*随时间的退化*成为被度量的量 ——它们是上面的理论变成一条可观测曲线的地方。

  • Mini-Uber — 多智能体运营的压力测试
    一个不可变的曼哈顿规模网约车仿真（需求、用户分布、拥堵、暴雨）。一个具有明确 coder 与 manager 角色的两层多智能体系统在不断升级的外部压力下维护一套派单代码库；指标是它能存活多久。引入外部竞争与监管信号后，存活时长大约减半。代码质量很早就开始下降——远在运行结束之前——manager 智能体滑向盲目预测与幻觉，代码库最终崩溃。
  • 面向长期存续仓库的终身学习基准
    一项系统综述发现，截至 2026 年初，没有任何长程编码智能体基准度量智能体独立开发并运营一个长期存续仓库的能力。构建了四个相互独立、几乎不含人写代码的软件项目，从开源仓库挖掘候选特性形成经专家审核的指令池，要求智能体针对抽取出的 issue 维护这些仓库。大多数架构远未到达预期时长便已崩溃，仓库质量分数持续下滑而非趋于平台。

已上线生产

这些都不是纸上练习——其中一个组件在我加入 PAVO 的第一个月就进入了生产代码库。

  • 动态上下文压缩 — 压缩率翻倍以上
    通读生产代码库后发现上下文压缩是基于规则的——只选取部分轮次内容，对当前轮次没有语义层面的压缩。搭建了一条双模型流水线（LLMLingua-2 + Qwen2.5-0.5B）做字节级过滤与压缩。在复杂工具调用上下文下，反事实消融确认智能体性能持平而压缩率翻倍以上。一周定位并演示，一个月作为 PR 特性落地；后续迭代按我共同设计的路线图移交工程团队。
