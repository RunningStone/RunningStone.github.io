这个站是怎么搭的：双语、静态、一个脚本

2026 年 9 月 6 日 · metatooling

本文译自原文，以原文为准： English

这个站点就是一个 Python 脚本。它读一份 BibTeX、两份 YAML 和一个 markdown 文件夹，把纯 HTML 写进 GitHub Pages 托管的 docs/ 目录。没有 Jekyll，没有 Hugo，没有 JavaScript 构建链。原因值得记下来， 因为我做大多数工具选型时用的都是同一套理由。

事实只有一个来源

发表列表是这个站上唯一会被别人核对的内容。它来自一份可以过 DBLP / arXiv 核查的 publications.bib， 所有提到论文的页面都从这个文件渲染。文字可以带观点，事实不允许漂移。

两种语言，两棵 URL 树

不用 JavaScript 切换文本，而是让每个页面存在两份：

English中文
/agent.html/zh/agent.html
/blog/<slug>.html/zh/blog/<slug>.html
/feed.xml/zh/feed.xml

右上角的语言按钮只是一个指向对应页面的链接，每个页面都带有指向另一语言的 hreflang。因此转发出去的链接 永远以发送者当时阅读的语言打开，搜索引擎看到的是两个真实页面，而不是一个会变形的页面。唯一涉及的脚本 只做一件事：把上次的选择记进 localStorage，在你访问根 URL 时应用它。

中文内容是英文结构上的一层*稀疏覆盖*——一份形状相同、只携带译文的 YAML。所有事实字段（发表 key、链接、数字） 都是继承来的，所以翻译不可能无意中引入新的说法：

def merge(base, over):
    if isinstance(base, dict) and isinstance(over, dict):
        return {k: merge(base[k], over[k]) if k in over else v for k, v in base.items()} | \
               {k: v for k, v in over.items() if k not in base}
    if isinstance(base, list) and isinstance(over, list):
        return [merge(b, o) for b, o in zip(base, over)] + base[len(over):]
    return over

没有后端的评论与计数

GitHub Pages 只托管文件，别的什么都不做。评论用 giscus：每篇文章对应站点仓库里的 一个 GitHub Discussion，数据和源码放在一起，读者用已有的 GitHub 账号登录即可。一篇文章的两个语言版本 指向同一个讨论串。

访问量由 GoatCounter 统计，它不存个人数据，也不需要 cookie 横幅。数字是否 显示在页面上是一个开关，默认关闭。

这套技术栈里每一件东西都过同一道测试：如果这个服务消失了，站点还能构建吗？三个答案都是能——最坏的情况 是少一个评论框。
