任务切分与通信瓶颈如何限制多智能体协作

2026 年 1 月 31 日 · agentsmulti-agentinformation-theorypaper

论文：How Task Structure Limits Multi-Agent Success: An Information-Theoretic Analysis，与罗鸣教授合作。这里用几个例子解释论文的主要结果，图表和公式均来自论文。“多轮 agent”一节是我在这些结果基础上的进一步理解，不属于定理本身。

三个人的补丁为什么合不起来

假设修复一个 bug 需要同时修改 parser、validator 和覆盖两者的测试。parser 的输出要符合 validator 的输入要求，测试则要检查两者的配合。如果把三个文件分给三个看不到彼此 diff 的工程师，各自的修改可能都合理，合起来却无法通过测试。难点在于文件之间的依赖关系，也就是图上的边。

多智能体系统（MAS）通常通过拆分任务来缓解单个 agent 的能力限制。但在一些复杂 benchmark 上，多个 agent 的表现反而不如使用同一模型的单个 agent。协调成本、错误传播和角色重复可以解释一部分现象。我们的研究进一步追问：任务本身的结构，是否也会限制协作系统的成功率？

任务中难以拆分的部分

我们把任务表示为约束图：节点是需要做出的决定，边表示决定之间的约束。每条边的熵 $H(\phi_e)$ 描述其中包含的信息量。一个任务里，有些部分容易独立完成，有些部分则包含密集的相互依赖。论文将后者称为不可约瓶颈 $\tau_{\text{hard}}$，下文简称“核”。

将核分配给 $m$ 个 agent，会切断跨分区的约束边。所有分法中，最小的信息切割量为

$$C_{\min} := \min_{\mathcal{P}} \sum_{e \in E_{\mathrm{cut}}(\mathcal{P})} H(\phi_e)$$

$C_{\min}$ 表示即使采用最优分工，也必须切断多少比特的约束信息。在这里，它由任务结构决定。

论文在六类常见图上，将闭式公式与暴力求解的最小割进行了比较。链只需要切一条边；八节点完全图在所考察的切分下需要切十六条。两者说明了任务结构的差别：顺序连接的工作容易分开，依赖密集的工作则困难得多。

信息缺口如何限制成功率

切断的边对应没有任何一个 agent 完整持有的约束。在论文的假设下，系统关于正确解 $\tau^\star$ 缺失的信息，至少与切割量成正比：

$$H(\tau^\star \mid \mathrm{Internal}) \ \ge\ c_1 \cdot C_{\min}$$

Internal 表示 agent 开始运行时获得的全部信息。因此，这一缺口在执行之前就已经存在。

缺少约束信息时，系统必须猜出答案的一部分。直观地说，猜对 $k$ 个未知比特的概率约为 $2^{-k}$。定理 1 在明确假设下给出了相应的成功率上界：

$$P(\text{success}) = O\!\left(2^{-\Omega(C_{\min} - H_{\mathrm{sol}})}\right)$$

$H_{\mathrm{sol}}$ 描述多个可接受答案带来的余地。答案唯一时，这一项为零，上界随切割量指数衰减。

在三色图着色的受控实验中，理论预测每切一条边会损失 $\log_2(3/2) \approx 0.585$ 比特。测得的信息缺口与这一预测一致：

内部通信能补上缺口吗

一个自然的办法是增加 agent 之间的通信。论文考察了封闭系统，也就是运行时不接收外部观测的系统。对于任意通信轮数 $T$，有：

$$I(\tau^\star;\ \mathrm{Internal}, \mathcal{M}^{(1:T)}) = I(\tau^\star;\ \mathrm{Internal})$$

在这里，每条消息只能由发送者已有的信息和此前消息产生。通信可以重新分配系统已知的信息，但无法提供系统原本不知道的解信息，因此增加带宽不会改变前面的上界。下图左侧给出一个合成实验：在 $C_{\min}=4$ 的网格上，通信量从零比特增加到一百比特，成功率仍在三分之一附近。

这个引理有明确的适用范围：系统封闭，且消息只依赖本地信息和已有消息。它约束的是成功率上界。通信仍然可以帮助 agent 更充分地利用已有信息、改善上界以下的表现。

外部反馈改变了什么

如果允许 agent 与环境交互，它就可以获得新的信息。令 $F$ 表示执行动作得到的反馈比特，例如测试失败、编译错误或用户纠正；$R$ 表示这些反馈中传回规划者的比特。定理 3 给出：

$$P(\text{success}) \le O\!\left(2^{-\max(0,\ c\,C_{\min} - F - R - H_{\mathrm{sol}})}\right)$$

指数项对应剩余信息缺口。当 $F + R$ 达到 $c\,C_{\min} - H_{\mathrm{sol}}$ 时，这个上界不再要求成功率指数级地小。上图右侧展示了同一网格上的变化：零反馈时成功率约三分之一，1.6 比特时超过九成，3.2 比特时实验全部成功。测得的转折位置与预测的 1.29 比特接近。

内部通信和外部反馈的区别，就体现在是否为系统带来了原先缺失的信息。前者调整已有信息的分配，后者可以缩小切分造成的缺口。

多轮 agent 放在哪里（我的解读）

论文比较的是多 agent 与单 agent。我也想用它理解另一个选择：什么时候应该拆分任务，什么时候应该让同一个 agent 多做几轮？

论文首先假设单个 agent 的容量为 $W$，即一次执行中实际能够利用的任务相关信息量。核超出这一容量时，任务拆分和多轮迭代是两种可能的应对方式。

拆分任务会产生 $C_{\min}$ 所刻画的信息缺口。在封闭系统的假设下，单靠内部通信无法补足它。

另一种方式是让单个 agent 反复执行、接收反馈，再继续执行。每轮能增加多少有效信息，受反馈通道容量限制。论文在 SWE-bench 上用测试结果的熵代理 $F$；一个通过或不通过的信号最多携带一比特。沿着这个思路，可以粗略地将相变条件换算为轮数预算：用 $(c\,C_{\min} - H_{\mathrm{sol}})$ 除以每轮获得的信息量。堆栈信息通常比单一的失败标记更丰富，因此可能减少所需轮数。这让我更关注工具能返回什么信息，而不只关注上下文能放多少内容。

这一解释仍有局限：论文没有显式建模轮数，真实 agent 每轮获得的有效信息也难以直接测量。它提供了一种理解我所观察到的现象的方式：有些让多 agent 协作失败的任务，也会让单个 agent 反复迭代很久。两者可能受同一任务瓶颈影响。

在真实模型上检验

合成实验中的 agent 按照理论假设构造，真实 LLM agent 则未必满足这些假设。因此，论文在 SWE-bench Lite 上检验的是四条方向性预测，涉及 46 个系统（18 个多 agent、18 个单 agent、10 个非 agent）、300 个任务和约一万五千条结果记录。每个任务的 $C_{\min}$ 由真实补丁涉及代码行的依赖图估计，再求精确的二分最小割。

四条预测的方向均与结果一致，且都达到统计显著，但效应量不大。论文讨论了几种可能原因：真实系统可以远低于理论上界；LLM agent 共享训练分布，可能通过隐式协调削弱非冗余假设；代码中的常见模式可能提供猜测捷径，而“无捷径”条件尚未在这些任务上得到验证。因此，这些结果支持继续研究任务结构的影响，还不足以将上界当作实际成功率的精确预测。

对系统设计的启发

  • 分配任务前先检查依赖关系。$C_{\min}$ 较小的任务更适合并行，依赖密集的任务需要仔细考虑切分损失。
  • 核较大时，尝试重构任务，减少跨 agent 的约束。
  • 设计工具时关注反馈的信息量，并为有效迭代预留足够预算。
  • 比较多 agent 分工和单 agent 多轮执行时，把任务结构、容量限制与反馈质量一起考虑。
