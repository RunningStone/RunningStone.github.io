Agents & Post-Training

I work both ends of the same problem. Theory tells me where long-horizon agency must break down — the limits that hold regardless of how well the system is engineered. Practice is the infrastructure that measures whether it actually does, and the post-training that pushes the boundary back.

The order matters to me: I prefer to characterise a failure mode before engineering around it. But neither half is worth much alone — a bound nobody can measure is a curiosity, and a benchmark with no theory of what it is bounding is a leaderboard.

Theory

The limits that hold regardless of engineering.

Information-theoretic limits of multi-agent success

An upper-bound theory of agent failure derived from task structure rather than from model capability: given how a task decomposes, there is a ceiling on what any multi-agent arrangement can achieve. Validated on SWE-bench, and carried through to the reliability mechanisms that follow from it — the bound is not the end of the argument, it is what tells the engineering where to push.

  • How Task Structure Limits Multi-Agent Success: An Information-Theoretic Analysis
    S. Pan, M. Luo

Lifelong learning under survival pressure

A full formalisation of lifelong learning whose point of departure from widely accepted frameworks is a constrained-learning view: the forgetting–plasticity trade-off does not operate in the abstract, it operates under survival pressure. To be submitted as an arXiv paper alongside a PAVO strategy document, with an accompanying benchmark (see Long-horizon autonomy below).

Loss of plasticity via manifold-preserving optimisation

Studied the relationship between the plasticity of MLP/CNN networks and their weight distributions. A manifold-preserving optimisation scheme achieved stronger anti-loss-of-plasticity behaviour. (In preparation.)

Practice

Environment → rollout → evaluator → reward → post-training, and back.

Evaluation: turning behaviour into signal

A post-training loop is only as good as the evaluator feeding it. Three complementary pieces: a deterministic-plus-judge harness for single-agent tool behaviour, a reproducibility layer that makes cross-agent comparison meaningful, and an automated generator for domain evaluation sets where hand-writing tests is prohibitive.

  • eval-box — deterministic checks + LLM judges
    Four deterministic checks (tool name, AST diff, argument consistency, output format) combined with LLM judges over a shared trajectory schema. Standalone, so it can grade any agent that emits the schema.
  • Controlled rollout protocol
    Produces comparable canonical JSONL trajectories across CLI agents under pinned sandboxes and explicit taint rules — the reproducibility layer without which cross-agent numbers mean nothing.
  • AutoGT — automated evaluation-set generation
    A domain-prior-guided agentic pipeline that extracts knowledge from a real enterprise software system and converts it into QA evaluation sets. The generated tests rank systems in strong agreement with expert hand-written tests while covering most expert-defined categories. Delivered into the product; methods paper under review.
    Paper · KDD-W
  • 27-operator evaluation spectrum
    An evaluation spectrum grounded in human working-memory and metacognition theory, applied as a systematic assessment across the three major closed-source model families.

Post-training for verifiable behaviour

Enterprise agent deployment is gated on guaranteed, stable service, not on average-case capability. I proposed programmatic process rewards as a self-initiated direction at PAVO: a neuro-symbolic framework that converts observed trajectory structure into a programmatic reward signal, which then drives a DPO/GRPO pipeline.

  • Programmatic process rewards → DPO/GRPO
    Fine-tuning Qwen2.5-0.5B this way improved it by roughly 10% over its own base on an internal tool-behaviour evaluation — primarily detection of illegal operations introduced via random sampling or context injection during tool calls.
  • Batched evaluation environments from seeds
    To make that evaluation possible, built an agent that uses an environment graph to construct tool lists plus differentiated Docker images with varying dependency libraries — yielding many test environments from a small set of seeds and an LLM.

Long-horizon autonomy under pressure

Short-horizon benchmarks hide the failure modes that matter. Both environments below are designed so that degradation over time is the measured quantity — they are where the theory above becomes an observable curve.

  • Mini-Uber — stress-testing multi-agent operations
    An immutable Manhattan-scale ride-hailing simulation (demand, user distribution, congestion, rainstorms). A two-layer multi-agent system with distinct coder and manager roles maintains a ride-matching codebase under escalating external pressure; the metric is how long it survives. Introducing external competition and regulatory signals roughly halved the survival horizon. Code quality declined early — long before the run ended — manager agents drifted into blind forecasting and hallucination, and the codebase eventually collapsed.
  • Lifelong-learning benchmark for long-lived repositories
    A systematic review found that as of early 2026 no long-horizon coding-agent benchmark measures an agent's ability to independently develop and operate a long-lived repository. Constructed four mutually independent software projects with minimal human-written code, mined candidate features from open-source repositories into an expert-reviewed command pool, and required agents to maintain the repositories against extracted issues. Most architectures collapsed well short of the intended horizon, with repository quality scores falling away rather than plateauing.

Shipped to production

None of this is an academic exercise — one component landed in a production codebase within my first month at PAVO.

  • Dynamic context compression — more than doubled
    Read into the production codebase and found that context compression was rule-based — selecting partial turn content with no semantic-level compression of the current turn. Built a two-model pipeline (LLMLingua-2 + Qwen2.5-0.5B) doing byte-level filtering and compression. Under complex tool-calling contexts, counterfactual ablations confirmed agent performance held flat while the compression rate more than doubled. One week to localise and demo, one month to land as a PR-feature; subsequent iteration handed to the engineering team along a roadmap I co-designed.
