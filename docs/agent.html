Agents & Post-Training

I study why agents fail during long runs. Some of this work is theoretical, examining limits imposed by task structure. Some involves building evaluation systems to observe failures, then using post-training to improve behaviour.

I usually start by characterising a failure mode, then design experiments and engineering changes around it. I want the theory to be testable and the evaluations to be clear about what they measure. Each helps refine the other.

Theory

Limits imposed by the task itself.

Information-theoretic limits of multi-agent success

This work derives an upper bound on multi-agent success from task structure. How a task is divided constrains the information available to the system, which in turn constrains its success rate. We tested the predictions on SWE-bench and used the results to study mechanisms for improving reliability.

Lifelong learning under survival pressure

I am formalising lifelong learning as constrained learning, with survival pressure included in the trade-off between forgetting and plasticity. An arXiv paper and a PAVO strategy document are in preparation, together with a benchmark (see Long-horizon autonomy below).

Reducing loss of plasticity with manifold-preserving optimisation

I studied the relationship between weight distributions and plasticity in MLPs and CNNs. In these experiments, an optimisation scheme that preserves manifold structure reduced the loss of plasticity. The work is in preparation.

Practice

Environment → rollout → evaluator → reward → post-training, and back.

Evaluation: turning behaviour into signal

My evaluation work covers three areas: checking single-agent tool use, making runs reproducible and comparable across agents, and generating domain evaluation sets when writing them by hand is too costly. The results also provide signals for post-training.

  • eval-box — deterministic checks + LLM judges
    Combines four deterministic checks (tool name, AST diff, argument consistency and output format) with LLM judges, using a common trajectory schema. It runs independently and can evaluate any agent that produces this format.
  • Controlled rollout protocol
    Records CLI-agent runs as comparable JSONL trajectories, with fixed sandbox configurations and explicit taint rules so that results can be reproduced.
  • AutoGT — automated evaluation-set generation
    Uses domain priors to guide agents in extracting knowledge from enterprise software and generating QA evaluation sets. The resulting system rankings agree closely with expert-written tests and cover most expert-defined categories. It is in the product; the methods paper is under review.
    Paper · under review
  • 27 cognitive-operator evaluations
    An evaluation suite based on theories of human working memory and metacognition, used to compare the three major closed-source model families systematically.

Post-training for verifiable behaviour

Enterprise agents need to deliver consistent service over time. At PAVO, I proposed programmatic process rewards: a neuro-symbolic method for extracting computable rewards from trajectory structure and using them in DPO/GRPO post-training.

  • Programmatic process rewards → DPO/GRPO
    Fine-tuning Qwen2.5-0.5B with these rewards improved its internal tool-behaviour evaluation score by roughly 10% over the base model. The evaluation mainly tests detection of illegal operations introduced through random sampling or context injection during tool calls.
  • Batched evaluation environments from seeds
    I built an agent that generates tool lists and Docker images with different dependencies from an environment graph. A small set of seed environments and an LLM can then produce a larger collection of tests.

Long-horizon autonomy under pressure

Some failures only appear after a system has run for long enough. Both environments below track degradation over time: changes in code quality, decisions and operating results, and how long the system continues to function.

  • Mini-Uber — stress-testing multi-agent operations
    A Manhattan-scale ride-hailing simulation models demand, user distribution, congestion and rainstorms; agents cannot alter its rules. Two layers of agents, coders and managers, maintain dispatch code under increasing external pressure. Adding competition and regulatory signals roughly halved survival time. Code quality declined early, followed by unsupported forecasts and hallucinations from the managers, until the codebase collapsed.
  • Lifelong-learning benchmark for long-lived repositories
    Our systematic review found no long-horizon coding-agent benchmark, as of early 2026, that tested independent development and operation of a long-lived repository. We built four independent software projects with minimal human-written code, extracted candidate features from open-source repositories into an expert-reviewed instruction pool, and asked agents to maintain the projects against extracted issues. Most architectures failed before the intended horizon, while repository quality scores continued to fall.

Work in production

In my first month at PAVO, I developed a context-compression component and submitted it to the production codebase.

  • Dynamic context compression — more than doubled
    Reading the production code, I found that compression selected parts of turns by rule, without semantically compressing the current turn. I combined LLMLingua-2 and Qwen2.5-0.5B for byte-level filtering and compression. Counterfactual ablations on complex tool-calling contexts showed similar agent performance at more than twice the compression rate. It took about a week to identify the issue and demonstrate the change, and a month to land it as a PR feature. The engineering team took over subsequent work using a roadmap I helped design.
